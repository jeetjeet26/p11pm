# Disaster recovery runbook template

This template records recovery objectives and evidence. It does **not** assert that Supabase PITR or storage backups are enabled until external verification is attached.

## Scope

- Organization/accounting export manifests generated by `scripts/export-organization.mjs`
- Local restore verification via `scripts/verify-organization-export.mjs`
- External backup verification via `scripts/verify-backup-evidence.mjs`

## Recovery objectives

| Metric | Target | Evidence owner | Last verified |
| --- | --- | --- | --- |
| RPO | 60 minutes | Platform admin | _pending external check_ |
| RTO | 240 minutes | Platform admin | _pending drill_ |

## Required external checks (still manual)

1. Supabase project PITR enabled and retention documented.
2. Storage bucket backup/replication policy documented for `project-files` and `workspace-chat-files`.
3. Isolated restore drill completed from latest export manifest with checksum match.

## Local verification commands

```bash
npm run db:reset
npm run test:db

node scripts/export-organization.mjs --organization-id <uuid> --output exports
node scripts/verify-organization-export.mjs --manifest exports/<uuid>/<stamp>/manifest.json
node scripts/verify-backup-evidence.mjs --project-ref <ref> --pitr-enabled true --storage-backup-policy documented
```

## Rollback evidence checklist

- [ ] Accelo promotion rollback attempt recorded in `production_audit_events`
- [ ] Source mapping journal restored where conflict-free
- [ ] Authority and schedule snapshot restored where safe
- [ ] Operator dead-letter queues empty or acknowledged
